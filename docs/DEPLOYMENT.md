# Deployment

The live site is <https://wikiverse.jonasjavier.dev>. The SPA is on Netlify, the Django API on
Render and PostgreSQL on Neon, all on free plans. Every push to `main` deploys what changed:
Netlify rebuilds the frontend, Render rebuilds the API when `backend/` changes.

## Topology

```
browser ──TLS──▶ Netlify ──┬── /             SPA (static, hashed assets)
                           ├── /wiki/<slug>   SPA for people; edge function sends link-preview bots
                           │                  to the backend's Open Graph shell
                           └── /api /admin /static /media /robots.txt /sitemap.xml
                                 │  (proxy rewrites, status 200)
                                 ▼
                          Render: wikiverse-api (gunicorn + Django) ──▶ Neon PostgreSQL
```

| Piece | Defined in | Notes |
| --- | --- | --- |
| Frontend | `netlify.toml`, `frontend/netlify/edge-functions/og-crawler.ts` | Builds `frontend/` with `VITE_API_URL=/api`; proxies backend paths so the browser sees one origin |
| Backend | `render.yaml`, `backend/Dockerfile` | `entrypoint.sh` waits for Postgres, migrates, collects static, then starts gunicorn |
| PostgreSQL | Neon project `wikiverse` | `pg_trgm`, `unaccent`, `btree_gin` are created by migration `articles.0003` |
| Redis | none | `REDIS_URL` is empty, so the cache and throttle counters live in each worker's memory |

The backend origin is written in two places: the proxy rules in `netlify.toml` and the constant
in `og-crawler.ts`. Change both if the Render service is renamed.

The backend is also reachable on its own `*.onrender.com` host. That is why security headers
and the CSP are emitted by Django as well as by Netlify, and why the login throttles key on the
username and not only on the client address.

Render's free plan stops an idle service after 15 minutes, and a cold start takes longer than
Netlify waits on a proxied request. `.github/workflows/keepalive.yml` pings `/api/health/`
every ten minutes to keep it warm; one always-on service fits in the 750 free instance hours a
month. GitHub disables scheduled workflows after 60 days without repository activity.

`frontend/Dockerfile` and `nginx.conf.template` are no longer used in production; they serve
`docker-compose.prod.yml`, the local production-like stack.

## Configuration

Variable **names** only; values live in the Render and Netlify dashboards and nowhere else.

**Backend (Render)**

| Variable | Purpose |
| --- | --- |
| `SECRET_KEY` | Django secret. Generated by the Blueprint. |
| `DATABASE_URL` | Neon connection string (direct endpoint, `sslmode=require`). |
| `DEBUG` | `false` in production. |
| `ALLOWED_HOSTS` | The custom domain, the backend's `onrender.com` host and `localhost` for the health check. |
| `CSRF_TRUSTED_ORIGINS`, `CORS_ALLOWED_ORIGINS` | The public origins of the frontend (custom domain and `*.netlify.app`). |
| `NUM_PROXIES` | `2`: client → Netlify → Render's proxy. Throttles read the client from `X-Forwarded-For`. |
| `DJANGO_SEED` | Leave `false`; seed explicitly (below). `true` reseeds on every boot. |
| `DJANGO_COLLECTSTATIC` | `true`. |
| `WEB_CONCURRENCY` | gunicorn workers; `2` fits the free plan's 512 MB. |
| `PUBLIC_BASE_URL`, `PUBLIC_SITE_DOMAIN` | Optional; default to the live domain. Used for sitemap, feeds and Open Graph URLs. |
| `SENTRY_DSN` | Optional; error reporting is a no-op without it. |
| `DJANGO_ADMIN_USERNAME`, `DJANGO_ADMIN_EMAIL`, `DJANGO_ADMIN_PASSWORD` | Read by `ensure_admin` only. |
| `REDIS_URL`, `THROTTLE_*`, `JWT_ACCESS_MINUTES`, `JWT_REFRESH_DAYS` | Optional overrides. |

**Frontend (Netlify)**

| Variable | Purpose |
| --- | --- |
| `VITE_API_URL` | Build-time, set in `netlify.toml`. `/api`, so the SPA calls its own origin and the strict `connect-src 'self'` holds. |

## Releasing

1. Merge to `main`. CI runs the backend (ruff, migrations check, OpenAPI check, pytest on
   PostgreSQL), the frontend (types, lint, unit tests, build) and the Playwright journeys.
2. Netlify builds the SPA; Render builds the API image if `backend/` changed. Migrations run as
   the backend boots.
3. Verify content, not just health — a green health check once hid an empty database:

   ```bash
   curl -s https://wikiverse.jonasjavier.dev/api/health/
   curl -s https://wikiverse.jonasjavier.dev/api/stats/
   ```

## Seeding production

Production content is seeded once, by hand, rather than on boot. Run the command from a local
checkout against the Neon connection string (Render's free plan has no shell):

```bash
cd backend
DATABASE_URL='<neon connection string>' python manage.py seed --epoch today
```

`--epoch today` ends the synthesised edit history on the day of seeding, so Recent changes has
entries in its default seven-day window. The command is idempotent and refuses to overwrite
content it did not create.

## Admin account

The seed never creates a superuser. Set `DJANGO_ADMIN_USERNAME`, `DJANGO_ADMIN_EMAIL` and
`DJANGO_ADMIN_PASSWORD` in your shell next to `DATABASE_URL`, then run
`python manage.py ensure_admin` the same way as the seed. Without `DJANGO_ADMIN_PASSWORD` it
generates one and prints it once to the terminal that ran it.
